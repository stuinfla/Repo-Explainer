# agenticow — Human Primer

## 1. What is agenticow

agenticow is an npm library that gives AI agents **Copy-On-Write (COW) vector memory branching** — described by the project itself as "Git for agent memory." The core idea: you maintain one shared base vector store, then fork lightweight branches off it for individual agents, users, or experiments. Each branch costs roughly 162 bytes and ~0.5 ms to create, independent of how large the base is.

The analogy to Git is intentional and precise. Just as Git lets thousands of developers work in isolation and merge through CI without duplicating the whole codebase, agenticow lets fleets of cheap models share one memory base while keeping their writes isolated, auditable, and instantly reversible.

It is the memory plane of the broader `@metaharness/*` ecosystem, pairing with `@metaharness/jujutsu` (the code/ops plane) to give agents a dual-state branch-and-rollback capability across both what they remember and what they did.

## 2. What can it do for you

Three things it makes cheap that were previously expensive:

| Use case | What it replaces | Cost with agenticow |
|---|---|---|
| Parallel agents share one base memory | N full copies of the index | N × 162 B, N × ~0.5 ms |
| Roll back a poisoned or hallucinated branch | Re-ingest + re-index from backup | Drop the branch, ~0.5 ms |
| Zero-cost checkpointing before risky steps | Periodic full snapshots | 162 B + edits-since per checkpoint |

**Concrete patterns demonstrated in the repo:**

- **Per-user personalization** — fork a branch per user; private edits stay isolated; storage is delta-only (KB per user, not a full copy).
- **Rollback/quarantine** — an untrusted agent ingests 100 unvetted vectors into a sandbox branch; discard the branch and the base is instantly clean, no re-index needed.
- **Checkpointing and crash recovery** — a 24-step migration checkpoints every 5 steps (162 B each); a latent bug found at step 24 triggers a sub-millisecond rewind to the step-10 checkpoint, then a corrective resume. No full replay.
- **A/B and multi-variant testing** — fork N variant branches, score each against a target, promote only the winner; losing branches are discarded for free.
- **Red-team sandboxing** — untrusted document embeddings go into a forked branch; a security prober gates promotion; exploit path triggers `rollback()` so the base is never poisoned.
- **Multi-tenant SaaS** — one memory-mapped base shared read-only by 1,000 tenant branches, each with private deltas; a cross-tenant isolation oracle verifies tenant A's queries never return tenant B's private data.
- **Multi-persona consensus** — 5 persona branches each propose an answer; an external deterministic judge (not an LM) picks the winner; only the winner's delta is promoted.

## 3. What is it made of (the components)

The repo contains **one component**: `agenticow`.

Its single external dependency is `@ruvector/rvf-node`, which provides the underlying RVF (Ruvector Format) storage. The knowledge base itself is indexed as a 384-dimensional RVF store containing 97 passages.

The library exposes **24 public symbols** and ships with **22 entrypoint commands** covering installation, benchmarking, acceptance testing, demos, and runnable examples.

There are no internal sub-package dependencies — it is a self-contained single-component library.

## 4. How it works

**Branching is Copy-On-Write.** When you fork a branch, agenticow does not copy the base vectors. The branch holds only a delta — additions, overrides, and tombstones relative to the parent. Reads are "read-through": a query on a branch searches the branch's delta first (child wins), then falls through to the parent base. This means branches are exact, not approximate, with respect to their own edits.

**The core operations:**

- `open` / `openBase` — open or create a base memory store with a specified dimension (e.g. 1536).
- `fork` — create a child branch; returns a branch handle with its own isolated write space.
- `ingest` — add vectors (with optional text) into a base or branch.
- `query` — top-K similarity search; on a branch, reads through to the parent.
- `promote` — replay the branch's delta into the base (or parent); only the winning/passing branch gets promoted.
- `rollback` — discard the branch's delta; the base is untouched, blast radius zero.

**Checkpoints** are snapshots of the delta at a point in time (162 B per checkpoint in the demonstrated examples), enabling rewind without full replay.

**Benchmark figures (AMD Ryzen 9 9950X, base=5,000 vectors, dim=64):**

| Operation | p50 | Throughput |
|---|---|---|
| fork (exact, derive) | 464 µs | 2,156/s |
| fork (native ANN) | 544 µs | 1,839/s |
| score (read-through query k=10) | 133 µs | 7,534/s |
| promote (replay delta) | 897 µs | 1,114/s |
| contradiction-check (1,225 pairs) | 1.228 ms | 997,250 pairs/s |

Per-branch storage at that scale: 0.84 KB.

**Vectors in the example suite** are generated by a seeded RNG (`_shared.mjs`), making id/order/recall outputs deterministic across runs (only timings vary).

## 5. How do I install and use it

**Install:**

```bash
npm install agenticow
# or, for the full MetaHarness stack:
npm install @metaharness/jujutsu agenticow agentic-jujutsu
```

**Minimal usage:**

```js
import { open } from 'agenticow';

const base = open('memory.rvf', { dimension: 1536 });
base.ingest([{ id, vector }]);

const branch = base.fork('user-42');
branch.ingest([{ id, vector }]);       // private to this branch
branch.query(queryVector, 10);         // reads through to base
branch.promote();                      // merge delta into base
// or:
branch.rollback();                     // discard, base untouched
```

**CLI:**

```bash
agenticow init   mem.rvf --dim 128
agenticow ingest mem.rvf --n 5000
agenticow branch mem.rvf --as user-42
agenticow query  mem.rvf.user-42.rvf --k 10
agenticow diff   mem.rvf.user-42.rvf
agenticow demo
agenticow bench
agenticow acceptance
```

**Run the examples:**

```bash
npm run examples          # all examples
node examples/personalization.mjs
node examples/rollback-quarantine.mjs
node examples/checkpointing.mjs
node examples/git-workflow.mjs
node examples/ab-branches.mjs
node examples/parallel-agents.mjs
node examples/red-team-sandbox.mjs
node examples/multi-persona-consensus.mjs
node examples/time-travel-debug.mjs
node examples/multi-tenant-saas.mjs
```

**Benchmarks and tests:**

```bash
npm run bench
npm run bench:ladder
npm run acceptance
npm run test
```

## 6. Honest scope and limits

**agenticow is infrastructure, not cognition.** The project is explicit about this: it is Git for agent memory, not a way to make agents smarter. The branching mechanics are production-ready; the "intelligence" of what runs inside the branches is entirely out of scope and depends on whatever models or logic you supply.

**The exotic examples are proofs-of-concept, not validated AI.** Patterns like parallel selves, memory evolution, and simulated organizations demonstrate that the branching mechanics work correctly. The judges and fitness functions in those examples are deterministic scoring functions — not validated intelligent agents. The repo states this plainly: "mechanics only."

**The judge must not be an LM.** The project's own scaffolding ablation found that a verifier-gated cheap-LM judge picks *worse* than a plain vote (a negative generation–verification gap). Wherever a judge appears in the patterns, it is a hard-constraint policy gate or a distance-to-rubric scorer — something that cannot hallucinate.

**Benchmarks are hardware-specific.** The figures above are from an AMD Ryzen 9 9950X at dim=64, base=5,000. Your numbers will differ.

**Dimension is fixed at open time.** You specify dimension when you call `open`; all vectors ingested into that store must match.

**The ecosystem dependency.** The MetaHarness dual-state bridge (ADR-202) requires `@metaharness/jujutsu` and `agentic-jujutsu` for the code/ops plane. If you only need vector memory branching, plain `agenticow` is sufficient.
